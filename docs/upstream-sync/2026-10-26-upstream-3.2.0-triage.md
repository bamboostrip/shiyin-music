### 1.2 架构差异（决定「能否直接回移」的根因）

| 维度 | 上游（kgka_Music_hl） | 本 fork（时音） |
|---|---|---|
| 数据通道 | Dart `lib/core/api_client.dart` 直接 HTTP 请求 `AppConfig.apiUri(path)` → 远程 .NET 后端 | Dart `ApiClientInterface` → `rust_api_client` → flutter_rust_bridge → `rust/src/engine.rs` 路由表 → `rust/src/services/*.rs` 直连酷狗 |
| `lib/services/music_api.dart` | ~2000+ 行单体类 | 1.8KB 门面 + `part` mixin 拆分（`music_api_auth/playlist/rank/artist/search/song/lyric/lyric_parser.dart`） |
| `lib/models/music_models.dart` | ~2400+ 行单体模型 | 367B barrel 文件，按域拆分到 `models/song.dart`/`playlist.dart`/`fm.dart`/`comment.dart`/`user_vip.dart`/`netease_external.dart` 等 |
| `lib/core/api_client.dart` | `ApiClient`（带后端 URL、token header、getRaw 等） | 仅 `ApiException` + `unwrapData`（600B） |
| 播放页 | `Navigator` 推 `PlayerPageRoute`/AppShell Stack 覆盖层 | 自研 `lib/ui/player/player_route.dart`（PageRouteBuilder，移动端上下滑入；桌面/车机横屏走 `DesktopPlayerPageRoute`）+ AppShell 内嵌播放条 + 桌面 Shell |
| 播放器内核 | just_audio | media_kit / 自研（Windows 桌面链路） |
| 平台支持 | Android + iOS（CI 构建未签名 IPA） | Android + Windows + Linux（PC 桌面适配、车机模式、平板重设计；无 iOS CI/Podfile） |
| 品牌 | KA Music（`kgka`/`ka_music` 标识） | 时音 `shiyin`（`10e66e6` 清零上游残留 + 老用户数据迁移） |

**结论：不能整体 merge。** 直接 `git merge upstream/master` 会在 `music_api.dart`、`music_models.dart`、`api_client.dart`、`player_page.dart`、`home_page.dart`、`app_shell.dart` 等 128 个同路径文件上产生大面积冲突，且会把「远程 .NET 后端」假设重新带回来。正确做法是**按提交→文件→函数粒度语义回移**，并同步补 Rust 侧路由/服务。本文 §3 已对每个提交给出文件级建议。
